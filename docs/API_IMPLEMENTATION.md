# 9288S 系统 API 实现清单

## 范围与证据

本清单只记录兼容层实际提供的 9288S 系统接口，不把“能进入某个画面”等同于
“API 已完整实现”。

接口名称、顺序、参数和返回值以原始 9288S 下载程序开发环境为依据：

`D:\Downloads\app_env_9288s_\app_env_9288s\Down_Include\RT_table`

重点参考文件：

- `RT_GUI.h`：`T_GUI_RelocationTable`
- `RT_FS16.h`：`T_FS_RelocationTable`
- `RT_OS.h`、`RT_Audio.h`、`RT_Dict.h`
- `gui/guiExt.h`、`gui/guiGdi.h`、`gui/guiWindow.h`

逐游戏次数来自当前仓库 `build/game-matrix` 中的动态探针日志。因此它们是
“已执行路径覆盖”，不是静态证明；尚未进入的菜单、关卡或异常路径仍可能调用新的
API。发布前必须同时完成静态导入扫描和逐路径动态回归。

开发环境还提供了一个带源码、ELF 和链接 Map 的官方样例：

`D:\Downloads\app_env_9288s_\app_env_9288s\build\测试.exe`

它已作为独立 ABI 回归程序接入宿主探针。当前可以完成创建主窗口、枚举当前目录、
创建并选择 12 像素字体、绘制 3D 控件框和文字，随后进入 `GetMessage` 消息循环，
没有未识别的系统槽位。该结果验证的是官方样例覆盖到的路径，并不代替四款游戏的
逐路径测试。

状态含义：

- **已实现**：参数、返回值和当前已覆盖路径的主要副作用均已实现。
- **部分实现**：当前路径可运行，但仍有缺失语义、固定返回值或仅支持有限对象。
- **等价空操作**：原调用在当前单窗口兼容模型中不需要额外工作，但保留正确返回值。
- **占位**：仅防止程序因未支持 API 退出，不能视为兼容完成。
- **待实机**：9588 模拟器已验证，尚未由 9588 真机结果确认。

## 9588 承接策略

- 图形：9288S 2bpp 图像、DC 状态和绘图原语先写入 RGB565 离屏帧缓冲，
  默认在 `EndPaint/UpdateWindow` 批量提交；输出按 PS for 9588 的受保护路径，
  通过 GUI 表取得并验证 C200 240×320 framebuffer 后写入 uncached alias，
  固件布局不匹配时才回退 `RenderPicture`。整个 BDA 生命周期复用一个 9588
  原生 Frame，程序列表与 EXE 切换时不销毁重建绘图上下文。另映射 S1C33L05
  `0x003c0000..0x003c9fff` 的 40 KiB 片内 VRAM；只在客体确实写入后，按
  160×240、每行 40 字节、每字节高位像素优先的 2bpp 四级灰度格式合成。
  每个系统 API 分发前先合成待处理的直接显存写入，保留“直接写显存后再调用
  GUI 绘制”的原始先后顺序。
- 输入：直接读取 9588 原始触摸事件和按键包，再生成 9288S 的鼠标、键盘消息；
  活跃循环不处理 Frame 窗口输入事件，Frame 事件泵只用于最终 detach。
- 计时：`SetTimer/KillTimer` 按官方 `(hwnd,id)` 语义管理最多 16 个计时器，
  使用 9588 SDK 单调时钟推进并向原 EXE 消息队列投递 `MSG_TIMER`。
- 文件：所有客体路径统一限制在 `应用/数据/9288s` 根目录内，保留原始目录层级，
  不按游戏名或存档名写死。
- 帮助：9288S `Help2` 由 9588 固件 Help Page 承接，不转换成消息框。

## LavaXOS 启动路径

用户提供的 v11 真机日志在 123 条客体指令后停止于 `GUI:447`。完整预处理
配置下的 9288S `RT_GUI.h` 将该槽位定义为
`void EnableStandBy(U8 benable)`；LavaXOS 启动时传入 0，语义是禁止待机。
9588 公开 SDK 没有应用级待机策略开关，因此兼容实现记录
`GUEST_STANDBY` 后成功返回，不修改 9588 固件的全局电源管理。

补齐该接口后，宿主探针继续发现并处理了两项运行环境要求：

- LavaXOS 会直接访问 S1C33L05 的 40 KiB 片内 VRAM
  `0x003c0000..0x003c9fff`。当前已映射真实可写 backing store，并按原机
  160×240、2bpp 布局输出；v12 首次观察到写入时记录
  `GUEST_IVRAM_ACTIVE`。
- `LavaXOS\LVM.bin` 为 454,450 字节。原 512 KiB 客体 heap 扣除窗口和运行时
  对象后无法装入；heap 已扩展为地址窗口允许的完整 1 MiB
  `0x02600000..0x026fffff`。
- LavaXOS 读取 S1C33L05 内部外设区的时钟寄存器。当前映射
  `0x00040000..0x0004ffff`，并由 9588 的 25 ms 单调时钟维护
  `0x40153..0x40158` 的分频、秒、分、时和日计数。

当前宿主探针可完成 `LVM.bin` 的 `stat/fopen/fread/fclose` 分块加载，扫描
`LavaXOS\Lava\*.lav`，并可按启动器枚举序号逐个进入 Lava 程序。探针会同时
注入窗口方向键/确认键和 `ScanGameComboKeys` 组合键，不把“只停在启动器首页”
算作程序通过。

2026-07-26 对体验版目录中的五个 Lava 程序分别注入 32,768 条消息，结果如下：

| 枚举序号 | 程序 | 执行的 S1C33 指令 | 可见 VRAM 写入 | 结果 |
|---:|---|---:|---:|---|
| 0 | 博士失踪记 | 519,323,602 | 3,308,800 | 正常回到空消息队列 |
| 1 | 性能测试 | 524,308,782 | 3,308,800 | 正常回到空消息队列 |
| 2 | 神州 | 517,454,596 | 3,308,800 | 正常回到空消息队列 |
| 3 | 蛙蛙富翁 | 526,859,535 | 3,305,600 | 正常回到空消息队列 |
| 4 | 魔塔 BW | 515,651,746 | 3,308,800 | 正常回到空消息队列 |

五项合计执行 2,603,598,261 条客体指令；已覆盖的自动按键路径没有再遇到
未识别指令、未识别系统槽位或非法访存。可用
`scripts/probe-lava-matrix.ps1` 重复该矩阵。动态探针不能证明未进入的菜单分支
也完整，9588 真机仍需逐项人工游玩和存读档复测。

程序运行时用到的 `btst [%rb],imm3`（`0xA8__`，实测首条为 `0xA874`）
已按 Epson S1C33 定义加入解释器和 MIPS32 JIT。

博士失踪记接收方向键、实际移动一步后还会执行同族的内存位操作；最先观察到的
停止点为 `0x02713418: 0xACF7`，即 `bclr [%r15],7`。当前已实现：

- `bclr`（`0xAC__`）、`bset`（`0xB0__`）的解释器与 MIPS32 JIT；
- `bnot`（`0xB4__`）解释器路径；
- 三者的一层/两层 `ext` 地址扩展、读改写边界检查及 PSR 不变语义。

修复后的方向键长探针已包含在上面的五程序矩阵中。触摸和实际程序运行画面仍需
用 v16 BDA 在 9588 真机复测。

雷霆战机共初始化 15 个 `MIXERSOURCE`：14 个为 8000 Hz、16-bit、mono WAV，
另一个为原始 16-bit PCM。长探针在资源成功读取后注入 4096 条游戏消息、执行
279,628,872 条 S1C33 指令并正常回到空消息队列，没有未支持 API、opcode 或
非法访存；带方向键、确认键和组合键的退出路径也正常完成 15 次
`MixerSourceClose`。

v15 真机日志随后覆盖到更晚的雷霆战机画面路径：`GUI:355`
`SysShowPicV(-41,239,200,13,...)`。这是一个 200 像素宽的精灵，只有源图
`x=41..199`、`y=0` 映射到虚拟屏幕最后一行；旧实现因源图宽度超过 160
直接返回故障。v16 改为按 SDK 声明的有符号坐标进行四边裁剪，并按原始图片
50 字节行跨度读取需要的 40 字节窗口。完全在屏幕外的绘制成功空操作，不再终止
客体；雷霆战机实际计算出的零或负宽高同样作为空绘制处理。精确几何参数已加入
宿主回归测试。

## CRTL 内存接口

CRTL 表在通用分发层内部处理，因此不出现在上面的 GUI/FS 探针计数中。

| 槽位 | 原接口 | 当前状态 | 缺口 |
|---:|---|---|---|
| 0 | `malloc` | 已实现 | first-fit 分配并复用释放块 |
| 1 | `free` | 已实现 | 释放块可被后续分配复用 |
| 2 | `calloc` | 已实现 | 溢出检查、分配和清零 |
| 3 | `realloc` | 已实现 | 原地扩展或迁移并复制旧内容 |
| 4 | `ansi_InitMalloc` | 已实现 | 重设客体堆区间 |

客体 heap 当前为 1 MiB（`0x02600000..0x026fffff`），可容纳 LavaXOS 的
454,450 字节 `LVM.bin` 及启动对象。分配器最多跟踪固定数量的活动块；长时间运行
仍需记录峰值和耗尽情况。

## C33→MIPS32 JIT

9588 端包含真实的基本块 JIT，不是把解释器改名：

- 把已支持的 S1C33 算术、逻辑、移位、扩展、乘法、特殊寄存器和 PSR 指令生成
  MIPS32 机器码；
- 支持最多两个立即数前缀与随后的寄存器/栈内存读写合并；内存访问仍通过边界检查
  助手执行，失败时安全回退解释器；
- 支持条件分支以及可编译算术延迟槽，分支条件在延迟槽执行前保存，PC 和指令数按
  S1C33 延迟分支语义更新；尚未支持的控制流和系统陷阱回退解释器；
- 使用 4096 个基本块槽位、16384 槽开放寻址哈希表和 1 MiB 可执行代码缓存；
  已编译块按 PC 平均 O(1) 查找，不支持的 PC 也进入负缓存，避免每次循环重新扫描
  及重复编译失败；
- 按 `gba-for9588` 的做法以 32 字节 cache line 同步 D-cache 和 I-cache；
- 每个新生成块第一次执行时，同时跑解释器参考路径和原生块，逐项比较寄存器、
  PC、PSR、SP、ALR/AHR、扩展状态和指令计数；
- 已验证的相邻基本块留在 JIT 调度器内连续执行，遇到负缓存或未编译 PC 才返回
  解释器，减少短块造成的 C 调用/返回开销；
- 参考路径按实际解释器指令计数推进，兼容一次 `c33_vm_step` 内执行分支和延迟槽
  两条指令的情况；
- 校验不一致时立即恢复解释器结果并禁用该块，不让错误状态继续污染画面；
- `9288LOG.TXT` v12 中的三个 `JIT_HEARTBEAT` 记录编译、校验失败、命中/未命中、
  回退、原生指令、负缓存和哈希探测数据；退出程序时由 `JIT_STATS_A` 至
  `JIT_STATS_F` 输出完整统计。`JIT_STATS_F` 额外记录 dispatcher 调用数、执行的
  原生块数和最长连续块数。心跳从每 2 秒降为每 5 秒一次，减少真机文件写入
  干扰。

用户提供的 v4 真机日志显示，旧实现会出现数十万次线性查找未命中及上百万次
解释器回退。对应优化完成后的 9588 模拟器回归结果：

- 五子棋：编译 1311 个块，约 248 万次缓存命中；JIT 原生执行约 668 万条，
  解释器回退约 198 万条，已覆盖指令中约 77% 走原生块；校验失败 0。
- 雷霆战机小缓存基线：512 槽位导致 393 次全缓存清空和约 20.1 万次重复编译。
- 雷霆战机 4096 槽版本：同类覆盖路径编译 1603 个块，缓存清空 0，重复编译量
  减少约 99.2%；约 1407 万条原生、376 万条回退，原生覆盖约 79%；校验失败 0。

用户提供的 v15 真机日志进一步显示，LavaXOS 长路径在 172.9 秒内执行
257,190,057 条指令，约 149 万条/秒。虽然原生 JIT 覆盖率为 87.6% 且校验失败
为 0，但 84,839,079 次缓存命中仅对应 225,276,309 条原生指令，平均每次命中
2.66 条，短块分发开销明显。

v17 同时修正宿主调度：

- `C33_VM_YIELD_TIMESLICE` 区分“10 万条指令预算耗尽”和客体
  `GetMessage` 真正空闲，只有后者才执行固件忙等；
- 保留每 10 万条指令一次的硬件输入和单调时钟服务，不以牺牲输入响应换速度；
- 外层时间片只在片内 VRAM 有新写入或原生 UI 标记重绘时转换、缩放并提交画面；
  未变化画面不再重复执行 213×320 双线性缩放；
- `SCHED_STATS` 记录时间片、客体空闲、真实提交及跳过提交次数，供下一份真机日志
  量化收益。
- `JIT_STATS_F` 可直接比较 dispatcher 调用数与原生块数，确认短块是否在一次
  dispatcher 调用内连续执行。

这些数字证明已覆盖块的语义一致并消除了已知编译抖动；v17 的实际加速比例仍须
使用同一 Lava 路径采集 9588 真机日志比较。

## 发布门槛

每个目标程序发布前必须满足：

1. 静态导入扫描和全部可达菜单的动态 API 记录没有未识别槽位。
2. 所有“占位”调用均证明对该程序无副作用，或改为真实实现。
3. 原 9288S 模拟器与 9588 兼容层的关键帧逐像素比较通过。
4. 9588 模拟器记录 API、解释器/JIT、帧提交和定时器性能数据。
5. 9588 真机逐项复测；模拟器通过不能标记为真机通过。
